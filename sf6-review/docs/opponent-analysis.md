# 一般ランクマとフレンド対策

## 1. 二つの分析モード

| モード | 対象 | 統計の単位 | 出力 |
|---|---|---|---|
| ranked_general | 本人がランクマと確認した試合 | 複数相手・キャラ・MR帯・パッチ | 自分の汎用課題、キャラ別課題、改善推移 |
| friend_focus | 本人が指定し同一性を確認したフレンド | opponent_id × character × patch | 相手個人の反応、条件別の傾向、人読み、対策プラン |
| mixed | アーカイブ内の両方 | 試合ごとにmodeを保持 | 別々の表と、比較できる範囲の対比 |

Battle Hub/カスタム部屋を画面からランクマと決めつけない。modeは画面表示とユーザー指定を照合し、判断できない試合はunknownに残す。一般ランクマの結果にフレンド戦を混ぜない。

## 2. フレンドの識別

opponents.yamlにalias、永続opponent_id、CFN ID（分かる場合）、正確な表示名の候補、使うキャラ、対象URLを設定する。CFN IDが動画に見えない場合はその値を映像から得たと主張しない。表示名の一致だけで別人の動画を自動統合しない。最初の試合一覧で本人が対象相手を確認する。

表示名変更はaliases履歴、キャラ変更は同じopponent_idの別characterとして保持。固定1P/2Pを前提にしない。既存公開URLのみを対象にし、相手のSNS等を調べる機能は不要。ゲーム上の行動だけを分析する。

## 3. 人読みとして集計するもの

全体の行動率より、刺激/状況に対する条件付きの反応を優先する。

| 条件 | 相手の反応候補 | 分母 |
|---|---|---|
| 相手の起き上がり | ガード、投げ抜け、暴れ、無敵技、ジャンプ、バクステ、不明 | 確認できた相手の起き上がり機会 |
| 自分の接近/ラッシュ | 小技、ガード、パリィ、DI、後退、不明 | 同程度の距離/ゲージでの接近機会 |
| 投げを受けた次の起き上がり | 投げ抜け増加、暴れ、無敵技等 | 投げられた後に次の起き上がりまで確認できた機会 |
| 打撃重ねを見せた次の起き攻め | ガード、パリィ、無敵技等 | 該当する連続攻防の機会 |
| 自分がシミーを見せた後 | 投げ抜け減少、歩き投げ等 | 前後の刺激を確認できた機会 |
| 相手が体力劣勢/ラウンドポイント | 無敵技、DI、飛び等 | その状態に入った機会 |
| 自分がD/SAを温存・枯渇 | 相手の接近手段/攻めの変化 | 同contextでの機会 |

投げ抜け入力は通常映像だけでは直接見えないことがある。空振り投げ等で確認できた事実と推測を分け、「投げ抜け入力率」を勝手に作らない。ディレイ投げ抜けと通常投げも区別できないならunknown。

## 4. 連続性と相手の適応

match_order、round_order、episode_order、直前の自分/相手の行動・結果、同じセット内の繰返し回数を保存する。P(相手反応 | 現在の状況, 直前の刺激)を観測する。

初期は直前1回だけ。短い履歴を大量に細分化して偶然の癖を作らない。十分なサンプルがあれば直前2〜3回のパターンに拡張。セット前半/後半、初回/繰返しで相手が対応を変えていないかを見る。

過去の同パッチ累積と直近セッションを併記し、変化があれば古い対策を固定しない。複数パッチをまとめない。サンプルが少ない行動には平滑化を使えるが、別のフレンドや全体キャラのデータを混ぜた場合はその寄与を明示する。初期MVPは生の件数と不確実性を優先する。

## 5. 自分の一般傾向との分離

自分がどの相手にも対空できていないなら汎用課題。特定フレンドだけ起き上がりで投げを受けるなら個別の条件を探る。同キャラのランクマ相手群は参考ベースラインとし、ランク/MR/パッチ/位置が違う比較を因果差と呼ばない。

特定フレンド×キャラの起き攻めEVはdocs/statistical-analysis.mdと同じ定義を使う。同じ表に「そのフレンド」「同キャラの他相手」「その他」を混ぜず、母数とcontextを表示する。

## 6. フレンド向けレポート

1. 対象のフレンド/キャラ、期間、パッチ、試合/局面数、本人確認、欠測率。
2. 確認できた癖3つ: 条件、反応率、件数/分母、区間、該当動画。
3. 自分がその反応で失った/得た体力割合と、起き攻めの観測EV。
4. 次のセットで試す対策: 状況ごとの選択、予想される反応、相手が変えた時の対応。
5. 検証指標と保留中の人読み。再戦後に以前の仮説が支持されたかを更新。

「次は無敵技が来る」等の断定ではなく、「この条件で観測回数x/n、直近は変化あり/なし」を示す。数字の裏付けがない人読みは検証仮説として扱う。

## 7. 保存と受入

DynamoDBのprofileはopponent_id × character × patch、分析データはjob_id/match_id/episode_idで参照。フレンドとランクマの集計対象をクエリで明示する。別名変更、左右入替、同キャラ対戦、表示名重複、同じ動画の再解析でも人物と件数が混ざらないことをテストする。本人が対象相手を解除したら以後の分析対象から外せる。
