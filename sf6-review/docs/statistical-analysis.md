# 統計分析仕様

## 目的

「自分は何を選び、どの状況で得失を出しているか」を数値で示し、改善優先度と練習課題につなげる。フレーム解析が不可能な映像に、数字らしい推測を付けない。

## 1. 一単位と分母

機会episode、match、round、session、opponentを分けて記録する。一連のコンボを被弾1回として数え、コンボの各ヒットを独立の判断ミスにしない。各ヒットはdamage_sequenceの子レコードとして保存する。

| 指標 | 分子 | 分母 |
|---|---|---|
| 自分の起き攻め打撃成功率 | 最初の打撃がヒットした起き攻め | 自分が打撃を選んだ起き攻め機会 |
| 起き攻め投げ成功率 | 最初の投げが成立した機会 | 自分が投げを選んだ起き攻め機会 |
| シミーの観測成績 | 相手の投げ空振りを誘って追撃した機会 | シミーと確認できた起き攻め機会 |
| 自分の起き上がり被弾率 | 起き上がり後に最初の攻防で被弾 | 自分が起き上がった機会 |
| 対空成功率 | 対空が成立した相手の飛び込み | 地上の自分に対する対空可能な相手の飛び込み |
| 対空失敗時の損失 | 対空失敗で失った体力割合の合計 | 確認できた対空失敗機会 |
| DI被弾率 | 相手DIに被弾した機会 | 相手がDIを出した機会 |
| 特定状況の被弾リスク | その状況で被弾した機会 | その状況に入った全機会 |
| 被弾原因の構成比 | その原因に分類した被弾sequence | 分類できた全被弾sequence |
| バーンアウト中の被ダメージ速度 | バーンアウト中の体力損失 | バーンアウト滞在秒数（通常時とも比較） |

対空可能性、シミー意図、確定反撃、暴れの判定が曖昧ならinferred/unknown。確反可能な技の全母数とフレーム表がない場合は確反率を出さない。特定状況の被弾リスクを出すには、被弾しなかった同じ状況も検出する必要がある。

## 2. 起き攻めの期待値

自分が有利な起き攻めに入った時点 t0（相手の起き上がり直前、定義を固定）と、t0から3秒後の体力を測る。ラウンド終了なら終了時を使用。途中で画面が切れた機会はcensoredとし、完全な機会と同じ平均へ混ぜない。複数の起き攻めが同じ3秒に重なるときはfirst_exchange_onlyの別集計も出し、二重計上を避ける。

`net_return = 自分が与えた体力減少（相手最大体力の%） - 自分が失った体力（自分最大体力の%）`

`observed_EV(action, context) = mean(net_return | action, context)`

表示例の形式だけを定義する。まだ実対戦の値は存在しない。表の列は「状況、選択、機会数、試合数、成功率、平均与ダメージ%、平均被ダメージ%、平均純リターン%、95%区間、欠測率」。

3秒と5秒の両方で感度分析する。長いコンボが3秒に収まらない影響を表示。別途「最初の攻防で確定したdamage_sequenceの総ダメージ」を測れる場合は記録するが、固定時間のEVと混同しない。後続位置/起き攻め継続/ゲージ消費は別列で表示し、恣意的に体力ポイントへ換算しない。

これは「自分がその選択をした場面で観測された成績」であり、戦略そのものの因果的な期待値/最適解を証明しない。投げを選んだ相手と打撃を選んだ相手が異なる可能性がある。機会がない行動の期待値や、試さなかった行動の結果は推定しない。

HP数値が画面にない場合はHUDのバーを校正して割合を測り、測定誤差を保存する。最大体力の異なるキャラに一律10000を掛けてダメージへ変換しない。正確なHP値を取得できたときのみ正確なゲーム内ダメージの列を追加する。

## 3. 状況別分析

初期のcontext軸: 自分/相手のキャラ、自分のサイド、中央/相手画面端/自分画面端、攻め/守り/ニュートラル、自分/相手バーンアウト、Dゲージ帯（0、0〜2、2〜4、4〜6）、SA、風破ストック、体力優勢/劣勢、相手MR帯（見える場合だけ）、パッチ。

初期の被弾分類: 相手飛び込み、起き上がり、通常技空振りへの差し返し、技をガードされた後、ラッシュ接近、相手DI、投げ、その他/不明。カテゴリは互いに排他的な主原因と補助contextに分ける。例えば「画面端・バーンアウト・起き上がり・投げ」を4つの独立ミスと数えない。

最初から全contextの直積を作らない。まず画面端×攻守×バーンアウトを集計し、機会数が十分な軸だけ追加する。同じ相手に多く負けた影響が大きければ、相手別成績を表示し、全体課題と区別する。

## 4. サンプルと不確実性

統計モードは全件、または対象本人の全試合集合から勝敗に依存しないランダム抽出。sample_seed、選択確率、除外理由を保存する。層化抽出なら層別に表示し、全体値には適切な重み付けが必要。印象的な負け試合だけを母集団へ一般化しない。

記述値は少数でも表示する。行動変更の推奨は初期目安として同context/行動30機会かつ10試合以上から。ただしこの閾値は有意性を保証しない。機会数に加えて試合数・セッション数・相手数を表示する。同じ試合の局面は独立ではない。

比率はWilson区間を参考にできるが、独立試行を仮定する区間を最終的な確信度と扱わない。主要なEV/差分はmatchを単位にcluster bootstrap（十分な試合数がある場合）、複数配信時はsession単位との感度分析。試合数が少なければ区間を安定した値として出さず「サンプル不足」と表示する。

unknownの率と、解析できた時間・試合のcoverageを併記する。既知成功s、既知機会n、不明機会uなら成功率の欠測感度範囲 `s/(n+u)` 〜 `(s+u)/(n+u)` を示せる。ただし機会そのものを見逃しているときはこの範囲でも解決しない。機会検出recallは手動ラベルで別評価する。

多くの状況を探索して偶然悪いセルを拾う問題に注意。探索的発見として表示し、次の配信をholdoutとして検証する。次の配信との前後比較でも相手/キャラ/パッチ/ランク分布が違えば改善効果を断定しない。

## 5. アドバイスへの接続

優先順位は観測損失の量、機会頻度、確信度、練習で変えられるかで決める。正確に改善できるダメージを計算したような説明はしない。

出力形式: 「状況」「数字と分母」「代表動画リンク」「可能な原因」「検証する行動」「練習方法」「次回追う指標」。数値集計はPythonコードが担当し、LLMに数を数えさせたり平均を暗算させたりしない。LLMは映像の分類候補と、計算済み統計の解釈を担当する。

例えば起き上がり被弾率が高いなら、相手投げ/打撃/無敵技読みの分類を確認し、単純な「常にガード」へ飛躍しない。打撃のEVが投げより高くても、投げを無くした場合に相手の守りが変わるので「投げをやめる」と断定しない。

## 6. 追加の受入基準

- 手動ラベルの全機会（成功、失敗、未知）に対してprecision/recallを検証する。
- 単一コンボの多段ヒット、窓の重複、3秒内の再ノックダウンを二重計上しない。
- 欠測時にゼロダメージ/失敗へ自動補完しない。
- 統計表の機会数がepisodeデータと一致し、同じ入力なら同じ値になる。
- 起き攻め、被起き攻め、対空の3指標から始め、精度が十分な指標だけを有効にする。
- 実映像に照合した数字以外は、テストデータまたは例であることを明示する。
